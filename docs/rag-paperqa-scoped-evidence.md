# PaperQA 子问题取证与重排适配

2026-10-24。仅为独立开发候选，不接入日常 LanCarbon，不修改用户模型配置或安装版本。继承[主体诊断](rag-paperqa-role-diagnosis.md)结论，不能用本文的离线通过代替真实学术验收。

## 适配边界

`scripts/paperqa_evidence.py` 不包含论文名、金额、金融主体分类或标准答案。保留 PaperQA 原生 Text/Docs 向量检索、Context/PQASession、最终回答和引用格式化。新增的编排为：

1. 现有 Flash 最多一次生成1—4个取证子问题及所选来源ID；只允许已选目录中的ID，检查来源覆盖。原始完整问题另作每个来源的检索任务，防止模型改写丢掉复合问题的一部分。子问题仍可能语义不完整，此结构检查不宣称验证其含义。
2. 对每个“子问题＋来源”使用原生向量检索，最多12个候选。只在该文件索引内查询，校验片段全文指纹及来源边界。最多8个所选文件、40个任务是本轮试验保护，不是新增产品限制。
3. 使用现有 `BAAI/bge-reranker-v2-m3` 对候选原文重排，返回全部候选索引/分数并检查重复、越界、非有限数和不完整返回。不以不同查询的分数绝对值跨任务排序，不设武断的空结果阈值。接口长段落分块参数遵照 [SiliconFlow 官方说明](https://docs.siliconflow.cn/docs/api/rerank-post)，本轮设 `max_chunks_per_doc=32`、`overlap_tokens=80`。
4. 先为每个任务保留第一名，再轮转补第二名；全文按来源与片段去重。最多28段、180000字符，必要任务超预算直接停止，不静默舍弃来源。重复片段保留其所有子问题关联。
5. 原文不生成摘要、不清理括号；稳定引用ID绑定来源、名称和完整原文。上游用片段名称作为书目键，因此仅在重名时对传入副本作来源消歧，不更改原始文件或原文。最后交给原生 `Docs.aquery` 一次回答，保持先前答案提示词和长度配置；不加入金融规则或额外核对模型。

索引恢复显式还原普通 Doc / 富元数据 DocDetails 类型，并检查目录与片段的稳定ID、名称和引用一致，避免上游联合类型验证把普通文档重解释为默认“未知文档”。保存—恢复回归在模拟材料中覆盖，五篇及额外两篇的实际缓存也已离线核对。原PDF的MD5与五篇索引的内容指纹一致。这是一般数据兼容修复，不含论文事实。

这是“一个规划＋一次回答”，不是恢复高调用量 ToolSelector 循环。向量与重排调用随子问题/文件数增长；本轮保留的旧长片段索引便于对照，尚未验证大规模知识库效率、精确页面跳转、多轮历史和安装包交付。

## 本地验证与真实范围

`tests/test_paperqa_evidence.py` 包含临床、交通、教育等虚构材料，检查复合问题原样保留、来源逃逸、缺失来源、恶意/损坏重排结果、第一名保留、预算失败、去重关联、完整内容引用身份，以及真实 PaperQA 类型/模板在模拟回答中保留两份同名片段的引用。另以原生 Docs 检索检查相同向量的其他文件不会越过来源隔离。10项通过；现有 `npm run test:rag` 213项通过、`npm run typecheck` 通过。Python候选检查需使用固定 PaperQA 环境运行，尚不属于默认 Node 测试命令。

真实阶段预先限定5个流程：原五文综合、两文方法比较、单篇数量与技术假设、额外 Caldecott/Pan 比较、五文综合的全流程重复。额外两文此前已使用过，只作不同资料回归，不称未见材料泛化验证。每流程先核对来源、原文和选择审计，再生成答案；不因答案出现问题不断追加同题重试。

沿用原10元账本，开始累计5.940634元、剩余4.059366元。不重置；网关对本阶段最多12次生成、150次嵌入、150次重排施加调用限制，并保留原10元含预留上限。新增模型或超预算需另获授权。完整私有输入/问答在已忽略的 `acceptance/` 内，审阅后清理，只保留最小结论和账本。
