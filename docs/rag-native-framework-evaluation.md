# 成熟框架的原生多文献流程评估

日期：2026-10-24。仅在 `acceptance/` 中运行独立候选，不修改或安装日常 LanCarbon。

## 范围与判断方式

- 用户要求同时推进科学文献项目选型与现有最佳候选 Kotaemon 的有限适配；优先试原生多文献能力，不以默认单查询配置评价整个项目。
- 固定现有 SiliconFlow Flash、BGE-M3；Kotaemon 使用现有 BGE reranker。PaperQA 使用其原生证据处理方式，不追加其他模型或外部论文搜索。
- 使用用户选定五篇论文，观察定义/计量对象比较、两部门方法比较、金额换算与技术假设。回答、检索覆盖、最终生成输入和引用分别检查；覆盖或引用字符串匹配不能替代事实核验。
- 不向流程提供标准答案、论文特定规则或人工挑选的正确段落。实验结果不自动代表其他论文、多轮产品交互或 Windows 安装包验收通过。
- 用户允许清理完整测试结果；保留费用账本、最小失败类型和本文件中的决策依据，原论文和日常资料不动。

## 已定位的差异

PaperQA 代理模式收集了五篇的证据，但有大量重复摘要。试验达到请求次数保护后，使用已有上下文调用原生 `Docs.aquery` 完成回答，不把这次保护中断归为上游答案错误。综合答案把煤电论文中“全部机组”与“存量机组”的两组金额解释为不同版本；原文包含范围限定，部分摘要省掉了它。该配置不合格，不能推论整个框架不合格。

Kotaemon 完整 Complex QA 的默认三子问题配置，在本题全部检索中覆盖四篇，最终原文只覆盖三篇。其上游最终步骤拼入子问题的答案，但未合并子问题的原文；因此前面读过炼油原文，最终仍表示缺少可核验原文。原生 `decompose_prompt` 配置加入所选文件目录并允许最多六个子问题后，实际生成五篇各自的问题及一个方法比较问题，恢复了 Mercure 取证。最终答案能讲到五篇，但原文与引用仍需要贯通。

## 有限适配的范围

Kotaemon 候选保留上游解析、索引、混合检索、重排、拆题、回答和引用组件。仅在 Complex QA 扩展点进行两项一般性调整：

1. 子问题阶段只检索原文，不生成中间答案；最终一次综合，避免把中间生成内容再作为证据。
2. 汇集子问题与主问题的原文，按稳定片段 ID 去重，以上游重排分数排序，每来源最多六段并轮转排列，继续受原生最终上下文预算约束；引用匹配使用同一组原文。

本地合并检查包含临床、交通两组虚构来源，覆盖来源保留、排名、去重、空正文与缺失来源。首题复用原生配置的已检索证据，只验证最终组织变化，不能称为完整适配链路验收；后续独立真实流程须分别标明。

PaperQA 的替代配置只使用上游 `evidence_skip_summary`、`partitioning_fn` 与 `Docs.aquery`：按来源分区取最多30段原文，跳过摘要，保留原生回答与引用。它是独立问题流程，不代表已经具备 LanCarbon 的跨轮聊天状态管理。

## 交付限制

全部测试在独立 Windows Python 环境运行，不需要 Docker。但完整开发环境大小不等于可交付安装包：Kotaemon 锁定依赖环境约2.91 GiB，PaperQA 约0.20 GiB；最终运行时裁剪和打包未验证。Kotaemon 原生 PDF 高亮渲染存在语言识别返回类型兼容警告，页面标签与物理页映射也尚未做阅读器端到端验证。不能据此宣称可直接随 LanCarbon 发布。

## 真实结果与选择

| 配置 | 真实验证范围 | 结果 |
| --- | --- | --- |
| PaperQA 代理/摘要 | 五文比较1题；含前期接线验证共91次生成 | 已覆盖五篇，但将存量/全体范围差异解释为版本差异；不保留此运行模式 |
| Kotaemon 原生 Complex QA | 五文比较1题，5次生成 | 检索覆盖4篇、最终原文3篇；漏 Mercure；原生文本匹配17/17不代表覆盖完整 |
| Kotaemon 原生按论文拆题 | 同题，8次生成 | 检索恢复5篇，最终原文仍3篇；引用文本匹配22/25，部分原文未贯通 |
| Kotaemon 保留原文适配 | 首题证据重放＋后两题完整流程，共5次生成 | 首题5来源、33/33引用文本匹配；第二题15/15，正确说明共同所有者不等于重复计算，但出现“MIX最低……高于另两路径”的矛盾；第三题6/6，核心金额、换算、差额、静态技术和名单缺口正确 |
| PaperQA 原生原文/分区 | 原五文3个独立问题＋额外两文1个独立问题，共4次生成 | 五文比较覆盖完整；第二题核心方法/共同所有者判断、第三题核心数值/技术问题正确；额外两文核心方法对照正确；五文概括仍把基金/养老金并列为最终所有者，不能宣称完整通过 |

额外两文是用户此前提供、本轮未参与设置调整的 Caldecott 2015 和 Pan 2023。核对了前者的暴露定义与公司组合说明、后者的方法及范围：风险暴露排序不同于情景化投资损失，Pan 并非利润 NPV 损失，也不能据两文推断企业实际损失排名。两个 PDF 共88页，原生解析为30段，本次30段均能进入上下文；此检查不证明超大知识库的选择性检索能力。没有在看完新答案后再调整配置。

**优先保留 PaperQA 原文/分区配置作为后续候选**：它的原生功能已经能完成上述主要取证任务，无需保留逐段生成摘要的高调用量流程；环境也更轻。Kotaemon 的适配证明了子问题原文贯通有效，但仍有生成矛盾且完整依赖较重，清理其大型运行环境，保留本文件与最小适配脚本供复现。该选择不等于 PaperQA 所有模式胜出，也不等于正式产品验收通过。

固定 Flash 的两条原文流程仍出现最终所有者层级混淆，而原文明确包含政府、个人及中间金融节点的区分。这一失败至少不能再归为“该段没检索到”，不应继续用论文专属规则修补。后续先保持候选和数据路径固定，将剩余生成错误单独评估；不要因相同错误重新开始无边界的框架轮换。

### 引用显示的小适配

PaperQA 在中文全角括号里能识别已使用的上下文 ID，但原生书目显示替换仅遍历半角括号，导致正文仍显示 `pqac-*`。在离线候选中，仅将包含已知引用 ID 的全角括号组归一化，再调用原生格式化函数；不改正文事实，不新增引用来源。已检查普通中文括号不变、半角输入不变、未知 ID 不会变成已知来源。原五文三题涉及的16/8/5个引用 ID 及额外两文对照的13个 ID 均有对应上下文，显示转换后无残留 ID。此修正尚未接入 LanCarbon。
