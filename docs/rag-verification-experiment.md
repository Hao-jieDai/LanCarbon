# 局部事实核对试验（已完成，未通过，不并入产品）

## 实际结果

三题各一次现有Flash调用，零重试，新增按返回用量与已有单价计得0.090688元；本轮保守累计10.847706/12元，含未知费用预留，不等于平台实际账单。产品与日常聊天未修改，未生成或安装新安装包。

三题均未通过人工复核。第一题修改范围和引文格式合格，但漏掉目标主体错误，还把原文已有的表述误判为没有；第二题新增引用未附对应证明而被拒绝，部分修改仍未厘清独立估计的关系，并遗漏错误的量级概括；第三题把正确金额当作单位错误，建议与原句完全一致，未识别目标排名错误。第三题严格引文匹配还受情景标识中的排版断行影响；不能把这种定位失败说成原文没有该数字。

结论是本原型没有显示可用的修复效果，不接入产品。程序范围限制与逐字引文匹配不是语义正确性证明；保留失败记录，不用同模型核对结果给自己打通过标记。授权的三次调用已用完，不继续付费重试或自动增加正式后台调用。原始材料、完整对照与账本仅在已忽略的acceptance/rag-2.4.13，私人资料不入版本管理。

## 为什么要试

当前候选的检索与解析修复已经由本地回归及真实原文验证。完整真实问答仍出现三类生成错误：将不同研究的估计值当作可拆分子项、混淆行为主体、将规模排序当作风险属性排序。同输入换模型及仅调整原文顺序，均没有稳定解决这些问题。

继续扩充一段常驻提示词不能证明能预防它们。下一步先做三题私有诊断，不直接改变日常问答流程，也不安装新版本。

## 拟试验的链路

现有流程：定位 → 检索/原文 → 一次正文生成 → 本地数学/引用检查。

试验流程：保留现有正文 → 使用当前所选 Chat 模型做一次原文核对 → 只返回少量有问题的原句与局部替换建议 → 程序校验范围及引文 → 人工比较原文与修改结果。

- 使用既有模型、连接和所选原文，不增加供应商、搜索、其他评判模型或数据来源。
- 核对关系、统计对象、范围、条件和关键数字，不评价文章是否“写得漂亮”。先核对原始证据，再判断待查句；不得把待查句本身当作事实。
- 试验最多三题，每题只增加一次当前 Chat 模型调用，不重跑整组，不自动重试，不进行整篇重写。
- 最多提出四处局部修改。没有证据的问题不得补写具体数字、主体或排名。
- 不擅自将核对结果视为真实正确。源引语匹配与 JSON 校验只证明格式及定位；关系推断是否正确仍须真实阅读。

## 请求与返回边界

请求包含当前问题、程序划分并编号的待查句和当前有效的原文及引用 ID。句子编号关联原文偏移与正文哈希，避免让模型逐字抄写整句造成定位失败。资料选择、指纹、原文和旧聊天保持不变。返回结构示例：

```json
{
  "changes": [{
    "claimId": "C3",
    "reason": "对象或条件与原文不一致的简短说明",
    "evidence": [{"citation": "S1", "quote": "该引用中的原文"}],
    "replacement": "仅替换这句的建议文字"
  }]
}
```

程序拒绝未知或重复句子编号、未知引用、过期证据、重叠修改、过多修改及不受支持的返回结构。重复原句由不同编号区分；补丁只能作用于指定偏移，其他正文保持原样。引文核验只规范空白与字母之间的行末断词，不删除负号、数值、百分号或实质词语，不使用宽松模糊匹配冒充支持。

核对请求失败或返回不可用时保留原始正文与费用，不能把失败当作“核对通过”；不会用第二次整篇生成覆盖它。实际界面行为待诊断有效后另行实现与测试。

## 费用和是否并入

用户已经同意三题小范围试验。只允许对已约定的三个失败案例各增加一次现有Flash核对；直接调用避免重复规划/检索，不自动重试。沿用用户已批准的整轮12元上限和现有账本，包含失败及未知用量预留。按现有Flash用量及价格粗估，新增三次核对约0.1–0.3元，每次仍须通过请求前预算检查。开始前保守累计10.757018元；这不是新增独立预算。

三题须逐项检查：既修正原来的错误，也没有新增数字、归属、范围或引用错误。无改善则废弃试验，不并入产品。即使诊断通过，也不等于完整学术验收通过；若以后启用正式流程，仍须新的完整多轮回归与隔离桌面测试，并向用户说明每轮增加的调用与费用。

## 本地验证计划

采用交通和临床等不同领域的最小案例，覆盖合法局部修改、正确正文不变、旧证据/未知引用、负号保护、空白断词、重复原句、重叠修改、损坏 JSON、网络失败、停止和费用记录。论文、完整个人聊天和密钥只留在已忽略的 acceptance/，不写入长期测试。
