# Library 外部修改与同步范围

## 文件夹操作

在 Library 左侧选中 Imports 子文件夹后，右侧提供 **Rename folder** 和 **Delete folder**。重命名同时修改磁盘目录并保持文档 ID、引用、版本和阅读进度。删除只移除文件夹本身：内容移到上一级，重名自动编号，确认框说明处理方式。

## 文件资源管理器中的改动

Library 的 **Delete** 和 **Delete selected** 是完整删除入口：确认后清理原件、版本、关联记录与写作引用，并关闭相关阅读标签、停止外部编辑跟踪。下表中的“保留缺失记录”适用于文件资源管理器中的外部删除，不适用于已在软件内确认的删除。

| 操作 | LanCarbon 的处理 |
| --- | --- |
| Imports 内新建、重命名或移动子文件夹 | 启动、返回 Library、Refresh 及运行期间每隔几秒检查并更新目录树；可识别的原目录保留 ID。 |
| Imports 内 PDF／EPUB 改名或移动 | 按文件身份和内容识别原文档，保留 ID、写作引用、版本及阅读进度。物理文件名发生变化时更新显示名。 |
| 往 Imports 直接复制新的 PDF／EPUB | 文件稳定且校验通过后在原位置登记，沿用格式和大小限制；与已保留内容重复的副本不重复登记，也不自动删除磁盘副本。 |
| 删除 Imports 空文件夹 | 目录树移除，不会因读取旧路径而重建。 |
| 删除文档或带文档的目录，或移出 Imports | 保留目录记录、文档和引用，标记缺失并提示恢复；不擅自删除记录或重新创建旧目录。 |
| 在默认程序中修改 **Open externally** 打开的文件并原地保存 | 跟踪 Library/.Editing 编辑副本，保存后生成新版本；关闭期间的保存于下次启动处理，内容不变不新增版本。 |
| 默认程序使用“另存为”保存到其他位置 | 不跟踪另存路径；需要另外导入该文件。 |
| 直接覆盖 Imports 的受管理原件内容 | 检查当前原件及导入文档版本的校验值并提示异常，保留磁盘内容，不伪造已经被覆盖的旧版本。恢复原文件，或将修改后的文件重新导入；需要版本管理时使用 Open externally。 |
| 直接覆盖、改名或移动 Library/assets 中的附件／图片 | 检查当前资源并提示内容变化或缺失，不自动重写写作引用。恢复原路径／内容；改显示名使用应用的 Rename，改内容使用 Open externally。 |
| 修改最初从电脑其他位置导入的源文件，或导出的副本 | Library 管理独立副本，不与外部源文件或 Exports 双向同步。需要时重新导入。 |
| 往 Imports 放入其他类型的文件 | 文件保留在磁盘；不自动登记为文献。其他类型通过 Note／Book 的 Attach file 添加为资料。 |
| 手工修改 Data 中 Notes、Books、聊天、配置或目录 JSON | 不是实时双向同步接口。应用运行时有内存状态和自动保存，直接修改可能被覆盖。日常操作使用应用；原始数据维护应先关闭并备份。 |
| 修改系统教程 LanCarbon: From 0 to 1 | 教程启动时按稳定 ID 同步，以安装包官方内容覆盖；不保留用户对系统教程的修改。用户自行创建的 Notes／Books 不受此规则影响。 |
| 移动或改名整个 Library、Data、Imports、assets 等系统根目录 | 不支持任意改根目录名。Data 使用 Data Location 迁移；移动整个工作区应保持内部结构。 |

## 识别边界

目录优先使用文件系统身份，旧目录记录使用唯一的内容和路径关系恢复。遇到多个相同副本、不可访问路径或无法确认的关系时保留原记录并报告问题，不猜测合并或删除。扫描不跟随符号链接或目录联接。

Imports 最多扫描 20,000 个项目、7 层子目录；单文件上限 100 MB。超限、无效文件和权限问题会提示处理。完整备份应包含 Data、Library（包括 .Editing）和 Config。
