## 产品约定

综合题“前N家对应金额/合计”原先被误分为逐家排名任务，导致无关的排名缺失说明，并可能把明确转嫁公式的留存部分误说成独立估计。现在只询问排序组的合计时按金额任务处理，明确逐家/名单/精确排名仍保留排名逻辑；区分同一基数经明确数学调整与独立估计，保留转嫁后留存部分的直接数量关系。交通与作物的不同基数/比例回归核对实际上下文中的原文与任务要求，不额外调用模型。

表格布局提示与一般保留规则仍可能被模型误读为只需两行；现在由本地解析显式“只/仅/only/删除”等限制，把默认保留的完整行数与行标签作为当轮明确输出要求（不包含旧数字），强调行不改变行集。否定的“不要只保留”不缩减，显式子集/删除仍按用户执行。临床/交通三行表与两行强调的实际输入回归覆盖整表要求、数值隔离、中英文和否定限制。规则不是格式正确性的证明，最终仍须逐轮核对真实输出。

连续真实验证还暴露无引用解释段重复写错已引用的基准额，并把两个已取证差额的演示求和按旧量级书写。新增局部金额证明：从当前引用原文重新验证前一金额段的值/币种/量级；只有具名重复值与同源、同量级派生差额的明确求和才可核对。标题/表格切断传播，其他场景标签、任意无引用文本、假设与代码不推断，冲突结果不修正；只验证数学量纲，不认可跨情景相加的经济含义。交通/作物的不同值与标签覆盖正向、幂等、跨章节和假设保护。仍不能保证所有中文省略标签、复杂公式和推论都自动核对，保留逐轮人工阅读验证。

本轮补充定位：真实回答可能在总额已正确换算后，将派生差额继续按旧量级书写。对于明确相减、具有可用引用的金额，修正器从同段原文同币种/同量级的单值计算差额候选，只修正数值精确匹配且量级唯一的情况；不证明比较的经济含义，也不修正互斥/歧义单位。明确声明按原文相减、整段仅有同一来源引用时，可核对该段计算句；普通无引用句不借用下一句来源。保留假设、代码、混合币种、低置信度OCR和孤立图标签保护，审计标明派生计算。交通/作物的不同数值回归覆盖幂等、原值与差额同步、多来源和非比较段不推断。算术校验同时支持普通/不换行/窄不换行的千位分组空格，避免只截取算式尾部误报。

- 资料来自用户为当前聊天选定的 Library、Notes、Books 页面及其显式关联资源。检索不得越过选择范围；改名、移动使用稳定身份，正文变化使旧证据失效。
- 继续使用用户已经配置的 Chat、Embedding、可选 Rerank；不偷偷增加模型、评判服务、搜索服务或收费步骤。开发测试默认离线，不能消耗日常 API 额度。
- 原文、写作、聊天、费用记录和模型密钥不因维护测试而修改。派生索引可重建，但不得代替原文件备份。默认价格仍为固定单价；分时计费已由用户暂缓。
- 用户关注自然阅读中的多轮问答：切换论文、比较论文、精确数据、证据引用和合理推论。直接回答并按需引用；真实缺口说明一次，不要求用户反复阅读检索免责声明。
- 本系统没有微调或训练模型权重。用户验收是应用评测；聊天不会自动改变模型能力。

## 实际链路与代码入口

1. `electron/knowledge-sources.ts`：把文件和写作转换成来源目录，展开选择范围。
2. `knowledge-store.ts`、`knowledge-extractor.ts`、`knowledge-worker.ts`、`src/shared/knowledgeText.ts`：提取、分块、指纹和文本缓存。PDF/OCR 等能力以当前解析器为准。 分块每片仍最多1200字符，优先在后半段的完整句末结束，其次为表格换行/词边界，保留有界重叠；不猜测缺失的定义尾部。超长无断句文本仍按上限分块。解析算法改变须更新解析器版本，旧索引自动重提取。
3. `retrieval-service.ts`、`retrieval-client.ts`、`retrieval-cache.ts`：准备向量、关键词/语义检索、可选重排和费用记录。
4. `chat-plan.ts`：识别当前对象、消解追问、规划比较与补查。新点名对象优先于上一轮焦点；同姓候选不等于同一论文。
5. `chat-grounding.ts`、`chat-context.ts`、`chat-evidence.ts`：在选定范围内组合语义候选、本地子问题候选、有效旧原文和必要结果段落，按预算选证据，并生成模型输入。 优先组包括显式表格追问、比较所需各文研究发现、真实子问题与规划查询；先保留每组前三条直接匹配及前两条的有界相邻原文，再加入自动方法/单位等组。公式和本地候选并入对应真实问题，不能把每个自动组当作独立用户问题。针对性规划查询先于通用逐篇补查，仍共享六次补查上限，沿用证据预算及资料/指纹检查，不新增模型调用。
6. `ai-service.ts`、`ai-client.ts`：沿用当前 Chat 模型按需规划并直接生成一次回答，保存正文、Thinking、证据和用量。
7. `chat-checks.ts`、`chat-quality.ts`、`chat-repair.ts`、`chat-claims.ts`：本地算术、金额单位和情景检查；仅对有引用、同币种、原文数值/范围精确对应且单位关系唯一的中文金额作程序换算修正，保留审计。按句子/表格行定位金额及其最近引用组，允许同句末尾引用覆盖并列分句；不同引用的金额分别检查，不从下一句借用引用。Markdown 表格允许从紧邻标题/题注继承同一来源的引用，逐行引用优先，新段落/章节结束继承；货币与单位写在列表头时同样识别。符号人民币列仅在原币数值已得到原文精确支持时按 e（CNY/USD）计算，不猜实际汇率。仅保护实际另造的假设案例，不因“例如”事实列举或论文报告的模型假设而跳过整段；无引用、原文矛盾和不确定 OCR 不自动改写；其余诊断仍不代表结论正确。
8. `src/components/AIChat.tsx`、`src/shared/grounding.ts`：呈现正文、引用和可展开 Evidence，跳转原文并验证身份。检索覆盖/单位等诊断只放在 Evidence，不在正文下方追加笼统警告；实际请求、读取与保存失败照常呈现。

`ai-client.ts` 保留完成原因，输出额度耗尽、过滤、错误或不支持的工具终止不能记为成功；继续读取尾部用量后报告失败，已有正文和 Thinking 保留且允许重试。只有 Thinking 而无正文也不算成功。`AIMessage.finishReason` 为可选诊断字段，不改历史消息。服务若以正常 stop 结束却输出不完整语句，传输状态本身无法证明语义完整，真实验证仍需人工阅读。

`chat-answer-plan.ts` 按定义、机制、比较、计算、写作和排名问题保留相应证据与回答指引。最终输入仅列当前有证据的来源；完整选择范围与无关来源诊断仍在保存的 grounding 中。近期同范围用户问题和当前来源焦点用于连贯追问，不把历史回答或用户假设当作事实。

表格换算/重排/核对追问除保留来源焦点外，还从上一轮实际引用中定位当前仍有效的原文；按来源ID、指纹和逐字文本重新核对，最多16条，各成优先组，使用同一证据预算，不增加API请求。不保留未引用的旧背景片段，不从旧模型金额构造证据；范围变更、显式切换论文、资料修改或删除时仍按当前来源重新检索。

资料模式不把旧模型正文作为事实输入；表格追问仅额外传递最近表格的列名/行标签（最多10列、24行，截短标签），不传递数值单元格，明确它只是未经验证的布局提示。换算默认保留全部行，用户强调某些行不视为删除其他行；明确请求子集时按当前请求执行。所有数值仍必须从当前原文取证。

`chat-completeness.ts` 在同一证据预算内补充研究范围与缺失单位的原文：范围候选优先方法/研究对象描述及图注中明确列举的指标部门范围，降低作者单位页眉的优先级。比较金额的复合问题同样保留方法、估值期限和基准证据。单位补查仅在当前来源和指纹下查找同币种、同数值且单位完整的原文，保留上界等限定，不自动合并为相同指标。邻段扩展后再补查一次，每次最多增加四个片段，不追加 API 调用。方法证据也覆盖同时问“为什么”和金额的问题，结合决策规则与静态/未来扩展限制。

`resultCoverage` 的历史原文与当前候选按同一结果质量排序，背景金额不能仅因曾出现过而排在该文总额前。初选、覆盖补检及邻段扩展后均保留各相关来源的定量结果优先级，仍使用同一原文预算。算术诊断按完整的有界加减乘除链检查，不截取三项和的后两项作错误比较；不执行表达式代码。

跨文献比较除了方法/定义，也为各相关来源保留实际研究发现：从摘要、结果、结论与明确的发现语言中选最多两段，每轮最多12个来源，放入同一证据预算；不增加模型检查或检索请求。不得仅凭研究层级或范围不同就否定某篇已经报告的结论。该覆盖只提供原文，不证明生成模型一定解释正确，仍需真实阅读验证。

`chat-formal-evidence.ts` 独立识别复合问题中的公式/定义请求，不能仅由整题的 mechanism/definition 等标签决定是否取证。按相关来源和原文数学符号、定义语言、通用中英文指标词选择候选，保留同页/邻近的变量和条件；每组最多四段、最多十六个请求和十二个相关来源，沿用最终上下文预算。保留各组所属子问题，补查后仍优先保留这些原文，不新增检索 API 或模型检查。不可把补充材料索引段当作正文没有公式的证明，不得推断补入 max(0,...)、求和范围或不清楚的 OCR 符号。未识别指标、复杂排版和大量公式仍可能需要进一步定位；这里只保证候选覆盖，不声称形式化验证公式。公式解释须保持符号与原文基准/情景及前后条件的对应关系；未请求且简单关系已足够时，不额外展开全套公式和变量表。

`src/shared/chatText.ts` 统一 Chat 显示、Copy、PDF 与 Note 的 Markdown/LaTeX 分隔符，保护代码，不猜测普通文本公式。运行时规范补充到已有自定义提示词中，不覆写用户设置；保存正文前先完成单位修正，再转义货币符号，兼容转义后的 US$，避免破坏金额识别。Thinking 保留原始内容。

所有含金额的证据都提供简短的程序换算辅助，不限于金额题；原始上下文已单独提供，不重复拷入换算字段。请求换算成人民币时，先以程序得到“亿美元”，再以未赋值的 e（CNY/USD）提供“亿元人民币”的符号换算，不读取实时汇率或用量页面汇率。每段最多8条，普通题仍最多3条；同来源重复换算去重，整轮辅助字段最多6000字符，不改变原文证据预算。附带金额与主答案同样检查。单位修正不把百分比猜成金额，也不为无对应原文的数字补造值；定性解释不额外罗列金额、网络节点数量或自行推算未被要求的金额。NPV 本身也是由现金流折现得到的存量指标，不能把财富损失与折现利润损失武断地分为互斥估值方法；聚合层级和估值方法分别比较。回答约束要求保留研究范围、估值期限/价格/折现及上界条件，不将按上市状态、行业或所有权阶段分组的数额擅自视为包含关系，不将“不能只看”夸大为“不相关”，并核对表格分项与文字归因。它们是生成约束，不能当成语义正确性的形式化证明。

图中的孤立金额标签缺少统计对象绑定，不能作为自动改正文单位或宣布量级冲突的依据。金额解析不跨行吞入下一标签的货币前缀。符号人民币列和原币列均可在列表头声明单位；只在同币种原文数值确定时计算目标数量单位，不引入实际汇率或跨来源推断。

原文英文并列金额可共用末尾的 million/billion/trillion，只有币种明确且一致、数字间仅有协调或范围连接词时继承共享量级，不跨单位、其他名词或混合币种。原文范围允许支持分别书写并重复单位的两个端点；不得将回答中自己的括号换算当作原文证据。金额辅助、诊断和修正同步识别共享量级，孤立图标签保护沿用。生成说明需区分原文原始单位与实际列表头单位，并明确说出比较双方，避免“前者/后者”反指。

中文并列数字共用末尾中文货币单位时按各成员计算，保留已正确换算的成员。原文金额后在同句出现不带币种的纯金额括号，仅在前文已明确单一币种、数值附英文金额量级时沿用；跨句、冲突币种、能量等其他单位不沿用。上述都是有限语法检查，不能证明设施、情景和年份等语义绑定一定正确。

表达事实与推断的区别依靠引用和“可能/更可能/提示”等措辞自然完成。已表达推断性质时，不再追加“这是我的解读”“摘录未直接说明”等重复自我说明；只在具体证据缺口实质影响结论时解释该缺口。保留科学假设、重要限定与真正的不确定性，不用输出字符串删除/替换来掩盖它们，也不改写历史回答。

`src/shared/chatNote.ts` 创建完整聊天的独立笔记快照，按回复生成唯一的笔记内来源锚点，保留来源标题、页码/行号。Thinking 和可选摘录按原始文字保存；超过 Note 上限明确失败，不截断。主进程串行追加，界面先保存当前写作，再采用返回的工作区并打开新笔记，避免旧状态覆盖新 Note。导出不调用模型，不改动原聊天。

## 本地 OCR

- `src/pdf-ocr.ts`：隐藏解析窗口中的本地 Tesseract.js；复用单个中英文 worker，按页释放图像。`scripts/prepare-ocr.cjs` 将固定依赖中的 worker、三种 CPU WASM 变体和中英文训练资源拷入构建；运行时不访问 CDN。
- `electron/ocr-store.ts`：按 PDF 内容 SHA-256 和原页码保存文字及坐标，64 MB/20,000 页上限，不缓存整页图片。新文件内容使用新缓存身份；改名、移动和相同内容的引用可复用。
- `knowledge-parser.ts` 优先原文字层，对无效/稀少文字页及数字相邻的单个缺失字形进行本地识别；不能把缺失字形猜成负号。识别仍失败时保留替代标记和needsReview，不以该页作为静默单位修正依据。解析器版本升级自动把旧记录标为pending重提取，不删除原件、选择和OCR缓存；不兼容的未来版本仍报错。用户手动重识别的页优先使用 OCR。每份最多 500 页、200 万字符，片段保留原页码、OCR 来源、置信度和需复核标记。
- `pdf-ocr-text.ts` 将坐标还原为 PDF.js text content，供正常选择、复制、搜索、翻译和引用跳页使用。原 `getTextContent` 内部使用 `streamTextContent`，适配时必须读取原始 stream，不能让二者递归调用。OCR 完成后重置受影响的 PageView 和 FindController。
- 解析任务串行、可取消，有进度与超时；已完成页面可复用。阅读识别变更会让对应派生 PDF 文本失效；正在准备的资料使用 revision 重试，不能为更新 OCR 而中断另一聊天的资料准备。旧的 partial/failed PDF 索引可自动尝试本地识别，已成功的普通文字索引无需统一重建。
- 置信度不是科学正确性的保证。对长整数与多个小数混排的可疑表格行提示核对小数点；不猜测补点。低置信度或有复核标记的 OCR 不作为自动金额修正依据。复杂表格/公式结构、旋转扫描、模糊页和加密 PDF 仍有实际限制。
- OCR 自身不调用 AI API；新增识别文本的 embedding/问答仍走用户现有配置和用量。测试只能使用临时目录，不可把实际论文或截图提交到 Git。

历史 assistant 正文不能充当事实来源。可以重新使用历史保存的原文摘录，但必须同时满足当前选择范围、来源指纹、片段身份和原文文本一致，且有当前问题的相关性。

## 问题定位顺序

先记录问题、选定来源、上一轮问题/焦点和实际证据，再判断：

| 观察 | 先查哪里 |
|---|---|
| 文件无法提取、表格乱码、扫描件无文字 | 解析与切块；不要先改提示词 |
| 问新论文却仍只搜旧论文 | 对象识别、继承规则、规划是否跳过 |
| 比较两篇却只有一篇证据 | 比较判断、来源约束和覆盖保留 |
| 正文有答案但候选没有 | 检索/重排/本地子问题候选 |
| 候选有答案但最终上下文没有 | 证据优先级、预算、去重及邻段扩展 |
| 正确原文已进入上下文，答案仍错 | 生成、单位解释、情景绑定与一致性检查 |
| 答案充满“本次摘录”“不是全文审计” | 最终提示词与内部诊断是否被当成答复要求 |

不要把来源选择数当成当轮证据覆盖数，也不要因一份资料的无关页无法提取，就认定其他已可读正文不能回答。

`test:rag` 验证范围隔离、来源切换、比较、子问题取证、有效证据复用、单位/算术及停止行为，全部离线。端到端测试同样使用临时数据和模拟网络。Windows 下 Electron 的加密与界面测试需在适合当前账户的环境运行；不要改用用户真实密钥规避测试问题。

当前用户对 2.4.12 本轮已将真实 API 总预算明确提高至人民币10元，包含Chat、Embedding、Rerank、辅助检查、失败和重试；只使用既有 DS Flash 与 SiliconFlow 免费 BGE，完整多轮验证后再交付。唯一未返回用量的中断请求按用户明确答复排除在预算之外，仍保留费用未知。该额度只适用于本轮，后续无新授权时仍沿用每轮5元限制，不解释为任意模型、任意服务或无限调用。每次执行前落实当轮资料/问题范围，并在请求前保守预留费用、记录全轮账本。

真实模型验收是另一层：需要用户授权的资料、模型和费用预算，记录版本/提交、来源指纹、问题顺序、检索证据、模型标识、用量和结果。人工判断主要结论、出处、关键金额/条件、追问连贯性及阅读体验；不能仅凭模型自己的充分性判断或一个分数放行。保留一部分未用于修复设计的新措辞/新材料，避免只对验收题有效。

RAG 相关更改运行相关回归；纯界面或其他无关改动无需反复付费跑完整学术问题。新失败应最小化成一般化案例，加入固定测试集后再修复。同一问题的通过标准应保持稳定；资料内容确实改变时才更新事实依据，并注明原因。

## 上下文与调用上限

以源码为准：最多 16 组用户子问题；补充检索最多 6 次；回答前最多 1 次 Chat 规划请求，使用所选模型；之后直接生成一次答案。简短自包含资料与已明确聚焦的问题可跳过规划，不执行模型回答后核对。新比较/歧义不能被“有不少片段”误判为已解决。

本地词法补查最多 48 个查询、每题最多 6 个候选查询，按题数分配配额，不调用 API；每个子部分先保留首个候选，再补充概述候选。最终证据仍有 96 片段和估算上下文预算上限。英文/中文字符估算不是平台账单 tokens。不要用无界循环或把全部文件无限塞给模型来替代检索。

## 维护与发布

RAG 内部修复更新 ReadMe；不把 Bug 历史写进系统新手教程。仅当用户操作方式或长期功能真的变化时，同步教程。更新当前交接、执行必要检查并提交 Git。安装前备份，使用独立目录验证，再安装到日常目录并核对数据与程序。清理安装包保留规则、Tag/Release 授权仍由根目录 `AGENTS.md` 规定。

验收通过表示约定范围达到要求，不代表任何资料/问法都不可能出错。后续问题应可定位、可复现、可回滚，而不是要求用户从头解释项目。

工作区保存还依赖 electron/storage.ts：教程同步、读取与保存共用队列，按资源锁→工作区操作的顺序进入；资源删除回调可重入，不能反向持锁等待。原子保存使用唯一临时文件和有界 Windows 替换重试，绝不先删目标文件。权限/共享 I/O 失败必须报告，不能误当 JSON 损坏而返回空数据。

显式算式后的金额等价换算由chat-repair.ts核对：两个操作数须在当前同篇引用中以相同币种/量级逐项验证，算式必须成立，再计算紧随其后的明确目标单位。支持尾数随单位改变的情况，不借用旧模型值、跨篇或不确定OCR，不认可比较/加总的经济含义。没有完整数学与原文证明时不自动改写。

所有完整金额量级模式从chat-money.ts同一MONEY_SCALES表生成，最长量级优先，中文复合单位两侧设边界；行内、共享单位、表头、符号换算和显式算式不得各自维护一个遗漏十亿等量级的列表。未知复合单位不按其较小后缀修正。正确原值/换算双列与计数列必须保持不变，回归同时检查误修正。

统一对象/条件规则同时区分基准固定参数、主情景实际变化及独立敏感性实验；敏感性结果不能自动当作主情景改变该参数的依据。若原始条件已在上下文而回答仍混用，应定位为生成问题，不继续盲目增加检索/改金额解析。
