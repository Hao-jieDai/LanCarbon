## 与失败笔记方案的区别

[旧逐篇笔记试验](rag-evidence-first-experiment.md)已经保留过引文和最终全文，不能把保留原文当作新保证。旧笔记仍包含模型生成的主体、指标、数值、单位和条件，可能改写关系、自行换算或漏掉限定。本轮去掉这些生成字段，只保留原句定位；精确引文仍不证明语义理解正确。

审查本地PaperQA源码：原生`summary`会改写摘要/相关性分数，`Docs.aquery`可接受现成`Context/PQASession`，`pre/post`会增加调用。本轮复用原生原文对象、引用和最终回答，不改上游仓库，不运行自由循环代理。

## 已实现接口

`scripts/paperqa_comparison.py`不导入网络客户端、不读密钥/配置、不创建模型、不持久化或重试，没有付费入口。

1. `build_packet`固定原问题、预先确定的比较维度、来源稳定键/标题/书目、原文块、位置和完整指纹。空原文、来源元数据冲突、引用ID碰撞、超限直接失败。
2. `locator_messages`只构造请求。未来获准后可用同一Flash一次性定位各文各维度原句，不是一文一次。当前仅模拟返回；维度由离线试验预先按问题确定，应用中的自动维度识别未接入。
3. `validate_map`要求来源×维度每项恰好一行，只接受`source/dimension/status/quotes`，拒绝事实摘要、改写、计算和解释字段。引文须逐字匹配对应来源指定块、位置唯一；程序生成起止位置及指纹。拒绝跨来源、假引文、重复JSON键、丢行、重复行、未知字段和过大响应。失败停止，不修补模型输出、不重试或悄悄退回基线。
4. `not_located`只表示定位器未找到，不能变成“文献没有”；仍保留全部原文。
5. `prepare_comparison`再次核对问题、来源、维度和原文未变，复用全文`prepare`及PaperQA原生最终回答。定位表作为导航数据加入，最终仍可读到所有未选中的原文与限定。禁止额外pre/post/旧答案迭代；通用说明只区分各来源陈述与跨来源推断，无论文名、金融结论或标准答案规则。
6. `citation_audit`只报告未知ID，返回`semantic_support=not_checked`，不替换正文或宣称引用支持成立。现有应用单位/算术检查保持原状；本候选没有另写Python金融修正器，也未将应用后处理迁入PaperQA。

简单问题继续使用未修改的全文一次回答基线。复杂比较候选未来预期一次定位＋一次回答，尚未接入应用，不新增第三次规划调用。

## 必须保留的限制

- 只验证来源、逐字匹配、结构覆盖；不能判断相关性、遗漏限定、比较维度是否完整或推论成立。测试包含真实引文却不支持结论的反例，要求检查器不宣称通过。
- 全部解析文本不等于PDF图像、表格和公式提取无误；原位置不等于精确阅读器跳转。
- 实验保护上限为8份来源、4维度、500000原文字符、40000引文字符，不改变应用文件数限制。超限失败，**自动完整章节选择尚未实现**，不静默截断后称全文。
- 自动路由/维度识别、Notes/Books、多轮、UI、费用与缓存接入均未实现。指纹失效检查不是已实现缓存。
- 定位增加输入、输出和时延，未证明成本收益或准确率。文档和定位表按数据处理，模拟输入检查也不证明模型抵抗所有提示注入。

## 下一轮配对试验与停止规则（未授权启动）

1. 固定代码和四组输入：两类旧综合失败、一题原本正确的复合数值题、一组未参与调试的新文献。现有七篇均非未见材料；新材料待确定，不能用合成样例代替真实未见文献验证。
2. A为Flash全文直接回答，B为相同原文加定位表再回答。来源、原问题、模型、输出/推理限额固定，维度在看到答案前确定。不得人工填正确引文或编辑中间输出再继续。
3. 首批四对最多12次生成：A一次、B最多两次。定位失败计候选失败，不重试。只有两类旧错误都改善、数值和新材料不退步、没有新增关键事实/关系错误，才在冻结配置下对旧综合和新材料各重复一对，最多再6次。否则立即停止，不因剩余预算继续加题、换规则重跑。
4. 分别记录机械检查、人工语义判断、关键遗漏、退步、时延和费用。中间定位错而答案偶然对也不证明可靠；有限样本不作普遍准确率保证。
5. 真实调用前再次确认材料、范围和预算。本次“开始”只授权离线步骤。没有稳定改善或费用高于收益时，放弃候选、保留全文基线及已知限制，不并入、不安装，停止这条方案的补丁循环。若改善，再另行安排产品接入和用户验收；不能把候选检查当安装放行。
