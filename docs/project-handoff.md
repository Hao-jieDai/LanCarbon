## 产品定位和阶段划分

LanCarbon 从笔记写作与网站发布工具扩展为**个人知识库**：Library 管理原始材料，Workshop 支持阅读与问答，Notes/Books 保存用户自己的理解和成果，Books 继续支持发布。文献自动发现和知识库自拓展是后续目标，不是 2.5.3 已有能力。

| 阶段 | 目标与当前状态 |
| --- | --- |
| 阶段 0 | 四个工作区入口、Library 资源迁移及基础布局；已完成 |
| 阶段 1 | AI 连接与 Chat、翻译、用量和费用管理；已完成，DeepSeek 官方入口已补入 |
| 阶段 2 | 文件导入管理、PDF/EPUB 阅读、最多十个阅读标签页、批量操作；已完成 |
| 阶段 3 | Library、Notes、Books 资料问答及 OCR，完善引用和聊天导出；按辅助阅读用途收尾 |
| 阶段 4 | 文献推送：按主题和来源发现文献，取得材料，按模板阅读、生成并归档；尚未实现 |
| 阶段 5 | 文献库自拓展：从已有材料回溯参考文献、跟踪施引和相关候选，受控补充知识库；尚未实现 |

阶段是开发沟通用语，不写入面向用户的教程或 Release 功能介绍。阶段 4/5 可以再拆分实现，但验收应围绕用户能完成的工作流，而不是要求用户评估内部索引或技术模块。

### Workshop

- **Run、Templates、Outputs 仍是 Coming soon 占位页。**相关目录及 `ResearchOutput` 类型不代表有可用任务引擎、模板编辑器或归档流程。

- AI 来源为 SiliconFlow、OpenRouter、DeepSeek 官方和 Others。Others 支持兼容 Chat Completions 的自定义连接。网络沿用电脑环境，不另建代理设置。

### 当前 RAG 边界

安装版采用 **PaperQA 全文优先 + 用户选定 Chat 模型**。来源可选 Library 文件、Notes 和 Book 页面，支持多轮问答和回到原文的引用。不是旧文档中“必须先配置 Embedding/Rerank”的流程。

已有 Embedding/Rerank 设置及旧检索代码仍在，但不能由此判断安装版在走向量召回。`npm run dev` 与安装版可能采用不同路径；修改安装版全文功能应使用 `npm run dev:paperqa` 或打包程序复现。

阶段收尾表示已交付辅助阅读工具，**不表示所有学术回答通过准确性验收**。历史单位、情景、主体层级及公式变量错误不能改写成已全部解决。关键内容仍需核对原文；已提供正确原文而模型解释错误时，不默认追加提示词、重搭框架或增加模型调用。

出现重大问题从 [RAG 更新指南](rag-update-guide.md) 开始，对照原文、解析、实际请求、模型原始输出、显示/保存五层证据。不得针对固定论文、问题或答案打补丁，不重启已停止的试验账本。无需在本文复制大量历史试验，当前边界与收尾结论见 [RAG 当前状态](rag-handoff.md)，历史试验结论见维护指南。

## 阶段 4：文献推送

### 目标及已确定的产品关系

用户希望最终形成“发现文献 → 获取原文 → AI 阅读 → 保存生成稿 → 归档 Notes/Books”的流程。原始文献属于 Library，AI 生成稿属于 Workshop/Outputs；二者分别管理并保留关联。

最初设计来自外部文件 `D:/Codex_Test/文献推送/LanCarbon_Research_Library_框架设计.md`（2026-10-12/13）。本文已提炼下一阶段所需关系，不依赖该文件在别的电脑存在。该文档是历史设计资料，不是当前实现或新的执行授权；其中 Research 名称、旧 RAG 路线及“三阶段”划分已被当前决定取代。冲突时以用户最新要求和实际代码为准。

### 建议实施顺序，需在开始开发时确认

1. **先确定最小来源范围。**明确主题的中英文描述、关键词/排除词、日期、文献来源、候选上限、阅读上限，以及手动运行/启动补查的行为。不要一次接入大量来源。
2. **建立任务与文献记录。**区分检索候选、去重后新记录、取得全文和生成结果；记录来源标识、DOI、文件身份与版本、处理步骤、失败原因及配置快照。
3. **接通 Library 入库。**复用当前资源 ID、哈希去重、版本、路径校验及变更通知机制，明确 AI-Paper 如何被目录、阅读器和 Chat 识别。原文获取失败留候选记录，不创建空 PDF 冒充成功。
4. **实现 Templates 和 Outputs。**先跑通一个小而完整的阅读模板，再扩展单篇速览/精读、多篇比较等。模板保存输入要求、输出结构和版本；生成稿记录实际读取的资料、阅读范围、所用模型及模板版本。
5. **实现归档和恢复。**保存到 Note 或指定 Book 位置，保留输出版本与目标映射。用户编辑后的正文不能被重新生成静默覆盖。重复操作不生成重复页面，归档失败只重试归档，不重新调用模型。

这些是建议拆分，不是已经确认的版本承诺。模型优先复用现有配置与用量记录；如新任务需要筛选、阅读等多次调用，必须在设计时说明用途、次数和预算，不能藏在自动流程里。

“推送”首先指软件内获得新文献和阅读结果，不自动意味着邮件、微信或系统外通知；外部发送渠道另行确认。初期按应用打开时运行与保存进度恢复设计，不默认要求常驻服务、Docker 或 WSL。

### 开始前应解决的具体选择

- 首批检索来源及各自实际能力：题录、摘要、参考文献、施引、全文链接、所需账户和限流。中文覆盖是否首批必需？
- 第一版仅手动 Run，还是同时包含启动补查；补查日期如何计算，停止后是否自动继续？
- 全文缺失时允许摘要速览还是等待用户补文件？精读模板不能拿摘要当全文。
- 首批模板、输出语言与格式；自动归档是默认关闭还是用户配置后启用？
- 下载、AI 阅读及归档的数量/费用上限；遇到单篇失败是否继续其余任务？
- 是否把 Outputs 直接加入 Chat 来源。本版只支持现有 Notes/Books/Library，不能假定 Outputs 已可检索；若加入，须标识生成稿版本，并保留原文入口。

### 用户验收应看到什么

- 给定主题、来源和时间范围，得到可核实的文献及清楚的处理结果。
- 有全文的材料可在 Library 打开，生成稿能说明实际使用哪些材料；缺全文不会被描述为已精读。
- 相同任务重复运行不会重复下载、重复收费生成或重复归档；用户主动重新生成另存版本。
- 停止、关闭、重启或网络失败后，可保留已完成结果，并只恢复未完成步骤。
- 生成稿进入 Notes/Books 后可正常编辑；再次运行不会丢失用户修改。
- 日常 Notes/Books 写作、阅读和 Chat 不被后台任务阻塞或破坏。

## 阶段 5：文献库自拓展

建立在阶段 4 的任务、候选、下载、输出及归档能力上，不再另起一套资源库。

| 扩展方式 | 预期作用 |
| --- | --- |
| 参考文献回溯 | 从已有论文找到其依赖的研究 |
| 施引跟踪 | 查找后来引用种子论文的工作 |
| 相关主题检索 | 从用户认可的主题或种子发现相关候选 |
| 缺失材料补齐 | 补全文、必要元数据或明确的新版本 |

每个候选保留种子来源、关系类型、检索依据和可验证标识。模型生成的题名或 DOI 不能未经来源核实便视为真实论文。同一文献从多个种子出现时合并关系，不复制原文；生成稿不是另一篇独立研究。

建议先限制为一跳扩展，设置主题边界、候选数、下载数、AI 阅读数及费用上限，再考虑更深层扩展。最新追踪和历史补库应有独立日期规则，不能用“最近七天”挡掉经典文献。候选是否自动入库、是否自动精读和归档，须由用户明确配置。

验收重点是：关系可核实、重复候选合并、经典材料不被误筛、数量和费用限制生效、缺文件可后续补齐，以及中断恢复不重复执行。阶段 5 不能退化为再加一次普通关键词搜索，也不追求无人约束的无限扩展。

## 数据、验证和发布约束

### 数据边界

开发仓库为本机 `D:/Codex_Test/笔记软件`；日常安装根目录为 `D:/LanCarbon`。这些是本机快照，不能硬编码到产品。`Application` 是程序，`Data`、`Library`、`Config` 等为用户数据；清理开发文件不等于允许删除日常数据。

当前路径由配置和路径函数解析：`Library/Imports` 放导入材料，`Library/assets` 放写作资源；`Data/Library` 保存管理数据，`Data/Research` 下有 Chats、Templates、Outputs、Records 等。生成稿、资源和任务的实际读写都应通过相应管理层；任务进程不得直接覆盖 `notes.json`，应与当前编辑状态合并保存。

`acceptance/`、`backups/`、`.dev-workspace/`、`release/` 等已忽略。不能提交密钥、完整个人聊天、原始论文、配置或备份。当前验证记录在 `acceptance/2.5.3-ui/`；此前 DeepSeek 更新记录在 `acceptance/deepseek-2.5.1/`；这是本机辅助证据，不是新克隆必须具备的文件。仓库测试使用公开可复现的小样例。

升级前确认程序已关闭并备份当前数据，安装后验证个人内容、配置、资源与快捷方式。回滚需匹配程序和数据备份；新聊天格式不能保证由旧程序读取。安装包清理按 AGENTS.md 和脚本执行，不自行扩大到备份或用户文件。

### 验证与费用

- `npm run typecheck`、`npm test`；RAG 相关修改另执行 `npm run test:rag`。
- 桌面、IPC 或打包变更运行相应 `tests/e2e`；模拟接口与真实学术验收分开报告。
- `npm run build` 生成生产程序；`npm run dist` 生成带运行资源的安装包。`npm run setup:paperqa` / `npm run dev:paperqa` 用于匹配全文方案的开发环境。
- 需要验证打包程序时，设置 `E2E_EXECUTABLE` 指向 `release/win-unpacked/LanCarbon.exe`；临时数据与日常目录隔离。涉及 Windows 密钥加密时使用正常用户权限，但不打印密钥或复制到日志。
- 最新 DeepSeek 更新记录：85 项相关单元测试、325 项 RAG 回归、类型检查/构建、7 项开发及 3 项打包桌面检查通过，并已实际安装核验。本次接手说明只修改文档，不重新声称跑过这些检查。
- 默认不调用真实 API。用户曾明确允许必要验证在单轮 5 元以内自主进行并在结束时报费；这不授权无限循环、新增后台调用或扩大测试对象。后续任务先判断是否属于已有授权范围；用户指定的更严格限制优先，需超额时先沟通。历史临时提高到 7/10/12 元的预算均不能继承为新轮额度。

### 发布与下一步

每次完成代码修改须提交 Git。内部维护文档本身不需要新增教程章节或重装程序。产品新功能/操作变化须同步 README 与内置教程；截图使用临时演示数据，不展示个人信息。

当前下一步是用户体验验收 **2.5.3**。只有用户明确要求“开始创建 Release 草稿”后，才冻结代码与版本并执行完整发布流程；正式发布仍需用户确认。本轮未推送代码、未创建 Tag 或 Release 草稿。

已讨论但尚未实施的后续拆分：**2.5.4** 增加 Notes／Books 多标签切换及统一右侧栏：Notes／Books 显示随页 AI 问答，PDF／EPUB 显示批注，左右侧栏互斥。具体版本可按用户后续要求调整，不因本轮交付自动开始开发。Mac／平板适配暂缓。阶段 4 文献推送、阶段 5 文献库自拓展仍未开始。
